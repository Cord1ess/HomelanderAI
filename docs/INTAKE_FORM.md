# Intake form — model-driven upgrade

**Branch:** `Dash/NewApplicant`
**Status:** In progress (implemented as of this writing per the workflow below).
**Read first:** [SPEC.md](SPEC.md) §1, [MODEL.md](Model.md), [DASHBOARD.md](DASHBOARD.md) §3, [DATABASE.md](DATABASE.md) §C. [DESIGN_POLICY.md](DESIGN_POLICY.md) governs *how*.

## What this is

The intake form (`apps/web/src/pages/intake/IntakePage.tsx`) moves from a fixed
TB-only questionnaire to a **model-driven** form. The operator picks which model
arms apply from a **vertical checkbox menu** ("click all that applicable"); each
selected model expands a **panel** with:

- an **instruction** telling the operator which **report/upload** must be
  submitted for that model, and **its own file upload** (Dropzone + per-model
  file list), and
- that model's **risk-factor fields**.

The applicant + coverage sections stay model-agnostic at the top. The Applicant
section is a **two-column grid**: a **required face photo** (identification only,
never a model input) on the **left**, and the client's **name, phone, date of
birth and sex** on the **right**. There is **no universal evidence dropzone** —
each report is uploaded inside the model that consumes it, so the form collapses
to **3 sections** (Applicant, Coverage, Models).

The **reference is generated by the database** (`applicants_ref_seq` →
`HL-<seq>` on `applicants.external_ref`) — the operator never types it; when the
backend is up the form fetches a preview, otherwise it shows "assigned on
submit".

## Data model

Fields collected per selected model are stored as a **per-model-keyed**
`declared_history` JSONB on `applications`, alongside a `models_requested` array
telling the orchestrator which arms to run. Each model's **uploads** live in its
own panel and are stored on `evidence_files` with a `model_arm_id`. The
applicant's **name, phone** and **face photo** (`face_photo_path`) sit on
`applicants`; the **reference (`external_ref`) is generated by the database**
(`applicants_ref_seq` → `HL-<seq>`). See [DATABASE.md §C](DATABASE.md) /
[§F](DATABASE.md) — **those sections are the authority and every change there is
highlighted `▶︎ CHANGED`** so DB-doc edits are unmistakable.

## Workflow (small-chunk commits)

One atomic, build/lint-green commit per step. Each step is committed before the
next is started. Both rounds are recorded below.

**Round 1 — model-driven form (7 model tabs via a vertical checkbox menu):**

1. **Docs config** — this file (workflow + registry).
2. **DB markdown** — update `docs/DATABASE.md` §C: add `applicants.height_cm` /
   `weight_kg`, `applications.models_requested` / `policy_term` (plus the existing
   C columns), and rewrite `declared_history` to the per-model shape. Every change
   marked `▶︎ CHANGED`.
3. **Schema** — mirror those columns into `db/schema.sql` (`applicants`,
   `applications`). `evidence_file_type` enum unchanged (modality recorded in file
   metadata, not a new enum).
4. **Form** — restructure `IntakePage.tsx` in one coherent commit (the registry,
   vertical checkbox menu, `selectedModels`/`modelFields` state, per-model
   panels with instructions + fields, XGBoost fields-only, required-upload
   gating all share the single file, so they are committed together rather than
   as artificial partial states).

**Round 2 — uploads move into each model's panel + required face photo:**

5. **DB markdown** — `docs/DATABASE.md` §C/§F: add
   `applicants.face_photo_path` (identity, no model) and
   `evidence_files.model_arm_id` + index, highlighted `▶︎ CHANGED`.
6. **Schema** — mirror `face_photo_path` + `model_arm_id` into `db/schema.sql`.
7. **Form** — replace the universal Evidence dropzone with a **per-model
   `PanelUpload`** inside each tab, and add a **required `FacePhotoUpload`** in
   the Applicant section. Form collapses to 3 sections.

**Docs:** `DASHBOARD.md` §3 rewritten at the end of each round.

**Round 4 — applicant name/phone + DB-generated reference + two-column layout:**

8. **Schema** — add `applicants.name` / `phone` and `applicants_ref_seq` +
   insert trigger that auto-fills `external_ref = 'HL-' || lpad(nextval,6,'0')`.
9. **DB markdown** — `DATABASE.md` §C add name/phone + DB-generated `external_ref`
   (and the "already right" bullet reversal), highlighted `▶︎ CHANGED`.
10. **SPEC** — dated reversal note in §9 (name/phone operator-entered; evidence
    still de-identified).
11. **Form** — two-column Applicant (`SimpleGrid`: face photo left, name/phone/
    dob/sex right), remove the manual Reference input, add a read-only
    DB-generated reference with a `GET /api/applications/reference` preview +
    "assigned on submit" fallback.
12. **Screen spec** — `DASHBOARD.md` §1/Submit rewritten for the above.

Verification before each commit: `npm run lint` · `npm run typecheck` ·
`npm run build` (in `apps/web`).
